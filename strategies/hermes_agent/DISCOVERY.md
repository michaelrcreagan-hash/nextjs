## Core Hypothesis

**No strong prior — this is deliberately unproven going in.** The user's own
answer: test empirically rather than assume an edge exists. The live
"Hermes" bus already runs a BTC directional ML ensemble whose own rolling
backtest reports 0.48 directional accuracy / 0.46 AUC — worse than useless
after costs — so hermes_agent does **not** inherit that as a validated
edge. It inherits it as a *component to test*, alongside three candidate
mechanisms surfaced during discovery but none pre-committed:

1. Breadth/agreement across domains (macro + technical + fundamental/
   sentiment + crypto flow) filters low-conviction single-signal noise.
2. Regime-conditional exposure scaling reduces drawdown rather than
   improving hit rate (the same mechanism the four-sleeve system in this

3. Faster reaction to real-time flow data (funding/OI/CVD/ETF flow) beats

## Exit Conditions

**Confirmed with the user: regime-scaled trailing stop.**

### Take Profit
No fixed take-profit — ride the trailing stop instead (see below). If
research shows a fixed-target variant meaningfully improves profit factor
(as it did for the AI-momentum desk's `scale_in` variant in
`trading/hedgefund/REPORT.md`), that's a candidate to test, not a default.

### Stop Loss
Initial stop from the setup's `stop_loss` level (ATR- or structure-based,
as already generated by the live bus).

### Trailing / Regime Scaling
Trail distance widens/tightens with the macro regime label — tighter trail
in RISK-OFF/CAUTION (protect gains faster when the regime says risk is
rising), wider trail in RISK-ON (let winners run). Exact trail percentages
per regime are a research parameter — start from this repo's existing
precedent (`ai_bottleneck_stocks`'s `trailing_stop_by_phase`: 20% early-
phase / 15% mid-phase) as an initial anchor, then grid-search.
